# 可独立打开的成品与轻量交付

## 制作工作区与交付目录分开

工作中需要原始资料、生成参考、临时脚本、阶段存盘和 QA 证据来定位错误；这不意味着它们都要提交到模型仓库。默认交付仅包含：

```text
<device>/<version>/
  model/<device>.blend
  model/<device>.glb
  model/<device>-web.glb
  previews/<final-view>.png
```

预览包含用户要求的各面、斜视和适用部件特写，保留最终独立图片；不要把 early/first/failed 图当成成品。版本目录和文件命名沿用项目规范，不为套模板改名或搬动已有资产。LFS 属性是必要的仓库元数据，可按设备目录保留。

把正式型号、主要模块配置、单位/坐标、来源摘要和估计部位写入 scene/object 自定义属性及语义对象名。轻量模式下不要让模型唯一的使用说明只存在于即将删除的 Markdown 中。用户指定完整审计包或需要可复现脚本时，再保留相应材料，不能用默认瘦身覆盖明确交付要求。

临时区由本任务创建并记录位置，完成后只清理自己拥有的工作文件。已有项目执行“仅保留成品、其余删除”时用**具体保留清单**，检查范围与当前 Git 修改，再删除清单之外的本任务文件。不要创建第二份庞大备份抵消瘦身，也不要自动清理别的设备、共享环境或 `.git`。

## Web 版：独立文件与大小上限

完整资产交付必须额外生成 `<device>-web.glb`，与原版 GLB 并存，专供网页加载。大小要求是 **文件本体严格小于 30,000,000 字节**，不是小于 30 MiB，也不是 ZIP、HTTP 压缩传输大小或 Git LFS 指针大小。原版已经达标时仍保留独立 Web 文件，可以复用其内容，无需为了区分而降低画质。用户明确指定其他上限或交付范围时按其要求执行。

只在导出副本上优化。优先清除无用数据、优化重复资源，再酌情降低非关键贴图分辨率/精度或简化不影响识别的细节。允许适度画质损失，但保留单位、坐标、型号/品牌、主要轮廓、端口/盘位/模块数量及挂耳真开孔；不能用封孔、改透明度或删关键部件来凑大小。

根据目标查看器选择压缩方式，不强制每台设备使用同一算法。省略显式切线可以缩小部分 GLB，但必须确认查看器能从位置、法线和 UV 重建切线空间，并比较法线贴图的反光变化。采用 Draco、Meshopt、KTX2 等扩展时检查目标网页所需的解码支持，不能新增未验证的运行时依赖。所有模型所需贴图应内嵌，不能把资源移到外部文件来规避单文件大小上限。

Web 版完成前实际执行：

1. 读取最终二进制 GLB 的字节数并验证 `< 30_000_000`，核对 GLB 容器及资源内嵌；不凭四舍五入显示的“30 MB”判定通过。
2. 独立加载实际 Web 文件，复核尺寸、坐标、组件数量、材质、Logo/文字方向和挂耳孔洞。几何被简化时重做相关结构检查；只移除可重建属性时仍要验证浏览器渲染。
3. 在实际浏览器查看器中与原版按相同相机和照明对比整机前后斜视、品牌/挂耳及接口近景，检查贴图、透明度、法线反光及所需解码器。加载成功不等于外观合格，格式检查工具也不能代替这一步。
4. 确认原版模型和不受影响的预览未被压缩操作改变，记录 Web 版最终文件名、精确字节数和验证结果。仍超限或浏览器检查失败时继续调整，不能将该项写为完成。

测试网页、依赖和比较图留在本任务临时区，不因增加 Web 版而恢复庞大的过程归档。最终仅额外保留通过检查的 `-web.glb`；需要展示 Web 特有外观时按用户范围提供对应最终预览。

## 清理前的四个实测条件

1. 主 `.blend` 已保存且没有未处理用户修改。纹理、字体及模型用到的外部资源已打包，路径可迁移；不能只看当前视口缓存。
2. 原版与 Web 版 GLB 实际资源内嵌，均已经独立回读验证，Web 版还通过上述大小与浏览器检查。若用户选择伴随外部纹理的其他格式，依赖文件就是成品的一部分，不能删除。
3. 保留的模型与最终预览逐个存在，预览对应最后一次可见修改。可在工作日志或内存记录 SHA256，检查清理前后未意外改变成品。
4. 让外部纹理不可用后重新打开主文件并复查使用中的图片、UV 和材质，再进行最终删除或提交。不要为重开验证另存 `.blend1` 到交付目录。

清理不修改模型几何就无需重渲染整套图。若模型修改，则更新受影响预览、导出与回读报告。明确区分阶段归档和当前交付主文件，避免用户打开错误版本。

## 最后保存与默认视图

任务使用可见 Blender 时，最后打开交付主文件，保留合适的整机 Material/Rendered 视图并停止动画。只改活动视口，保存后重开检查默认视图和打包资源；超时按执行状态恢复方法处理。

把报告、校验和与工具日志放进完整审计包时，避免自引用哈希：校验清单不能包含自身；若检查报告在校验后生成，需要明确其排除规则。轻量模式不需要为每个运行步骤永久保存一份 JSON。

## Git 与 LFS

用户已授权提交/推送时直接完成；未授权的发布不能由技能自动取得。提交前检查当前分支、remote、暂存区与远端变化。只暂存目标设备或本次技能目录，不使用全仓库 `git add .`；保护其他任务的未提交修改。需要新分支时遵守项目命名规范。

大型 `.blend`/`.glb` 应在暂存前确认项目范围的 LFS 属性及可用 LFS，避免先产生巨大普通 Git blob 再删除。环境缓存、虚拟环境、渲染临时文件不提交。属性示例放在设备目录，按实际格式调整：

```gitattributes
*.blend filter=lfs diff=lfs merge=lfs -text
*.glb filter=lfs diff=lfs merge=lfs -text
```

检查暂存路径、LFS 指针的 oid/size 和本地对象完整性，完成适合本次修改的格式/链接/资产检查后提交。推送要确认 Git 与 LFS 上传都成功，并比较远端分支 SHA；本地 commit 成功不等于交付已推送。

远端并发更新导致非快进时，先查看新增提交和冲突，按仓库正常流程同步、重验再推送。不要循环强推或改写他人历史。认证、分支保护或重复网络失败时保留具体错误与已完成提交，报告实际阻塞，不虚报成功。

普通删除提交缩小当前工作树和后续检出内容，旧 blob/LFS 对象仍可能存在于历史或本地缓存。清除 Git 历史/远端存储属于另一种高影响操作，需要明确授权；不能把工作目录从数百 MB 减到几十 MB 描述为整个仓库历史也已缩小。

## 最终消息

给出原版、独立 Web 版及预览位置，注明 Web 文件精确字节数及实际做过的关键验证、重要估计范围和提交/推送状态。瘦身任务说明当前设备目录大小即可，不把历史存储算成已经回收。不留下“可以继续导出/提交”的半成品承诺。
