# 执行可靠性与验收

## 沿用当前工作环境

先读项目/工作台适用说明，检测 Blender 版本、当前文件、场景、未保存状态及可用工具。任务要求可见 GUI 时，沿用现有实例，保存当前作品或副本后隔离新任务，不能清空尚未保存的其他模型。背景 Blender 可负责已经保存的预览/QA 渲染，不能冒充 GUI MCP 建模或真实桌面操作。

未要求 GUI 的纯 headless 环境可以按授权范围使用 CLI，但如实区分覆盖范围。GUI 只是可用时，不代表文件检查任务需要唤起或切换它。用户明确要求的桌面验收无法执行时，它仍是未完成项，不由后台相机图代替。不要把特定服务器路径、DISPLAY 或 Blender 版本写成技能的永久依赖。

发现 MCP/桌面工具并查询实际 schema；备用协议调用器仅在当前环境确实存在时使用。若 Blender 工具要求 user_prompt，传用户当前任务的原话，而非自编阶段说明；上下文变更后遵循新的用户范围。脚本统一项目根路径，通过 exec 调用时显式传入 PROJECT_ROOT 或绑定 __file__，不要散布上一次工作台路径。

CPU/软件 OpenGL 大批量修改先用 Solid，材质检查时切活动视口即可，不让所有工作区同时编译材质。检查当前构建是否支持降噪；若不支持对应后端，同时关闭最终与预览降噪选项。

## 超时不等于失败

大操作分段，每段具备可识别的完成标志和保存状态。非幂等阶段重跑前查询对象、集合、文件 mtime/大小与日志，判断是还在运行、已经完成还是确实失败；不要立即重复创建几何或杀死用户 GUI。

在回调内 open_mainfile 后，旧 scene、screen、area 和数据块引用都可能失效。打开文件与后续操作分成不同调用，等界面恢复后重新取当前引用。

后台渲染只在保存完成得到确认后启动。记录输入文件哈希或能验证的阶段属性；MCP 仍在保存时提前 dispatch，可能读取旧模型。若发现这种情况，停止仅属于本任务的错误渲染进程，以正确快照重启，不能让旧结果混入最终预览。

长任务在工作区维护简短状态：锁定配置、坐标、当前文件、已完成阶段/修复、运行中调用、未完成项。不要把历史“尚未开始”与最新“已完成”堆成互相矛盾的状态。最终轻量交付不需要携带全部运行日志。

## 真实桌面记录

动态检测当前桌面和原始截图分辨率；RDP 断开不等于桌面已注销。每次按坐标点击/拖拽前取新截图。若原图 2560×1440 被显示为 2048×1152，操作坐标要换算；这只是历史例子，不能硬编码。

在真正 3D 视口的空白处取得焦点，用一次实际输入验证角度变化后才开始整圈。鼠标停在工具栏/Outliner/控制台时，KP_6 的“sent”可能没有旋转模型。操作后等待重绘，必要时重查姿态，不能读取旧帧后宣称成功。

记录实际键鼠输入、时间、视口位置/距离/四元数和原始截图。整圈应包含连续中间姿态，而不只是首末相同；四元数 q 与 -q 代表同一姿态。只累计绝对角度会让左右往返误过关，需要检查单向绕轴的进展与闭合。补充俯仰、顶底、近远距离、耳片和接口特写。模型近景导致真实遮挡时，从正确外侧调整视角，不删除正式装配来拍得“通透”。

辅助脚本用于固定俯仰、绕同一世界轴的一整圈记录：

```bash
python3 scripts/check_orbit.py /work/device/orbit-frames.json
```

脚本路径相对**本技能目录**，输入路径指向设备工作区。输入是带 `q: [w,x,y,z]` 的帧列表（或 `{"frames": [...]}`）。有截图文件时使用 `--asset-root /work/device` 检查帧中的相对 `screenshot` 路径。它检查记录的数学一致性，不能证明输入来源、图像内容或工具调用真实；仍需核对桌面工具日志和截图。任意变化俯仰的轨迹不适用这套固定轴判定。

## 结构测试与视觉测试互补

| 覆盖 | 检查方法 | 不能据此声称什么 |
|---|---|---|
| 型号与数量 | 实拍人工计数 + 场景语义组件清单 | 同一脚本生成并计数不能独立证明配置正确 |
| 尺寸与轴 | 世界变换后的主壳/整机/耳片边界；回读后再次量测 | 数字误差小不代表估计细节达到制造精度 |
| 几何 | 负变换、重复面、退化、体积/边界、倒角、外部穿模 | 正体积不代表每个孔或可见结构都正确 |
| 法线 | 平面几何与分裂法线比较；弧面特写 | 面积大不必然是平板；不要把弧面作为错误例外伪造通过 |
| 文字/UV | 节点引用、非对称符号、阅读轴、重开和回读 | 缩放全正不保证未镜像 |
| 材质 | 逐面 material_index 与实际材质槽、基材 Alpha/Transmission/剔除、数据色域、当前光照 | 正确节点不证明面引用了该材质；OPAQUE 不证明网格没有漏面 |
| 外观 | 六面、斜视、近景与同型号同配置实拍并排，检查真实比例、材料质感与工厂标识；动画/卡通/示意风格判为返工 | 数量正确或画面精致不能代替与真实设备外观一致；缺失面不可拿其他型号整机照证明 |

阈值按模型单位、最薄材料和实际间隙选取并记录。旧模型的 0.01 mm 尺度容差、1e-7 m 诊断焊接或某个法线 dot 阈值不是所有设备的固定门槛。不要为了通过测试而放大容差吞掉真实结构。

## 耳片与壳体不透明专项

1. 复制两侧耳片到独立测试场景，不改正式模型。隔离副本中移除测试螺钉，放高对比双色或棋盘背景。
2. 检查正反、左右侧、斜视和掠射角。孔中心射线不能命中耳板；孔旁金属射线必须命中，记录位置、命中对象和外向法线。
3. 另做透明 RGBA pass：隐藏或移开仅用于测试的棋盘/双色背景几何，并启用透明背景输出；背景存在时孔后像素也会是 Alpha 1。棋盘可视检查与裸 Alpha 检查是两张不同结果。在无遮挡孔中心与金属内部取小像素区域，避开抗锯齿边缘。孔中心应近零 Alpha，金属内部近一。混合边缘属于覆盖率，不等于金属透明。
4. 回到正式装配，分别核验背景可见、被螺钉遮挡、被机身遮挡的孔；不要求所有孔透明。
5. 对顶底左右本应封闭的多个分散区域做射线和 RGBA 内部采样，并在浅/深背景查看；实际通风孔不算漏空，不能用整机平均 Alpha 掩盖局部错误。
6. 在独立重导入的 GLB 上重复这些测试。模型尺寸、孔位和数量不同，重新选择测试点；不要复制上一台机器的固定坐标。

若浅/深背景是同一 RGBA 渲染的合成，明确注明合成方法，不冒称重新照明。像素 Alpha 与几何射线都通过后，还要查看实际孔壁和材料是否合理。

## 闪烁与表面异常排查

| 症状 | 优先排查 | 对应修复 |
|---|---|---|
| 相邻面黑线/随角度闪烁 | 重复共面、墨层间距、近远裁剪精度 | 调整实际结构或微小间距、合理 clip，不无限抬高贴花 |
| 孔板星状反光 | 错误平滑/分裂法线 | 只修应平坦区域，保留倒角 |
| 金属像石材、黑塑料发灰 | bump/粗糙度幅度、未知环境、过曝 | 校准物理纹理尺度与光照 |
| 材质节点正常但部分面呈默认灰色，或 glTF primitive 异常大量拆分 | 越界 material_index、空材质槽 | 确认预期材质后按槽修复，重渲染并核验实际导出文件；不靠调亮节点或压缩掩盖 |
| 细孔网远距波纹 | 像素采样摩尔纹 | 近看与高分辨率复查，不删除真实孔网 |
| 只在运动/某种模式噪点 | 尚未收敛、Eevee AO/反射与 Cycles 差异 | 等待重绘/采样，报告实际渲染器差异 |
| 重开标签黑块/漂移 | 丢失 UV 名、旧 RNA 引用、外部贴图丢失 | 重绑定、打包、保存重开再验 |
| 拉手弯角扭折 | 扫掠截面方向跳变 | 连续标架及合理弯曲几何，不靠双面或平滑隐藏 |

## GLB 容器与真实回读

只导出正式装配；排除工作灯光、相机、背景、参考平面、QA 夹具及隐藏文字源。确认使用的纹理可内嵌。默认 glTF Y-up 转换由导出器处理，避免预先旋转后又转换一次；回读到 Blender 后核对原坐标。

只读辅助工具：

```bash
python3 scripts/inspect_glb.py /work/device/model/device.glb --self-contained
python3 scripts/inspect_glb.py /work/device/model/device.glb --self-contained --opaque-material "Ear steel" --opaque-material "Chassis metal"
```

脚本路径同样相对技能目录。工具报告容器、资源、材质及三角面统计；只对显式点名的金属材质执行不透明/单面合同，不一刀切拒绝有依据的透明零件。默认只输出 POSITION accessor 的数量；需要逐项声明边界时加 `--include-position-bounds`，这些值仍不是世界包围盒。它不是完整 glTF 验证器，也不解码图片、量世界包围盒或证明流形/UV/孔洞。缺失材质名应作为配置错误处理，不能静默跳过。

在独立场景或实际可用查看器中导入导出的文件，重新验证尺度、组件、法线、UV、标识、材料与孔洞。区分独立网格三角数和实例展开数量；记录实际使用的扩展、法线图强度、图片尺寸及是否有外部依赖。格式/压缩扩展不是普遍坏事，目标查看器必须支持；不支持的性能选项不得成为隐含依赖。

材质索引修复后，在相同中性光照下重新渲染；保存重开主文件后再查逐面索引，实际重导入 GLB 后核对每面索引是否落在有效材质槽内且指向预期材质。导出后索引可以重编号，不能只对比原始编号；材质名存在或材质表正确也不能代替面分配检查。异常 primitive 数量是排查线索，不能单凭数量判定错误。

额外交付的 `-web.glb` 不能沿用原版的通过结论；还必须满足 [Web 版大小与浏览器验收](delivery-and-git.md#web-版独立文件与大小上限)。优化后文件本体须小于 30,000,000 字节，并在浏览器中实际加载、对比关键视角。

修复后更新对应证据和报告的源文件哈希。保留失败记录直到复查完成；错误测试覆盖与真实模型错误要分别说明，不能把未执行的检查写成通过。

两个辅助脚本使用 Python 3.9+ 标准库，不依赖 Blender 或网络。维护脚本时，从技能根目录运行 `python3 -m unittest discover -s tests -v`；这些合成输入测试不替代真实设备的视觉与几何验收。
